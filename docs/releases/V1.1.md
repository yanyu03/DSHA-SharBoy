V1.1 以 **Kaeru（`main`）** 为稳定发行基准，采用逐项审查、独立测试、可逆合入的方式吸收 Fatfish 的成熟成果，**不进行 Fatfish 分支整体合并**。仅列入已经落在 `main` 的变更；Fatfish 中尚在实验、未完成验证或未合并的代码继续留在研发分支，不作为 V1.1 功能承诺。

## 本次更新

### 1. 更容易上手的 README

- 新增“小白快速读懂”，解释 DSHA 的用途、Index/Router、EnvFeel、Gate/BaseTool 与执行结果/追踪记录。
- 新增面向 Agent 的仓库阅读和最小任务引导提示词，强调先检查环境、权限、命令及回滚，再执行。
- 增加问题反馈说明：优先 [GitHub Issues](https://github.com/yanyu03/DSHA-SharBoy/issues)，邮件 **yanyujiangnan03@gmail.com**；反馈请附版本、复现步骤和脱敏日志。
- 增补架构与七阶段生命周期图示、KDI-01/FatFish 原型状态及 M8ven 徽章说明。徽章仅反映第三方平台展示的验证信息，不等于全面安全认证。

### 2. Kaeru 路由安全收紧

- 从 Hamasaki 选择性吸收 fail-closed 意图路由与显式 argv 检查，修改 `scripts/router.py`。
- 新增 `scripts/test_kaeru_router_safety.py` 回归用例及 `.github/workflows/kaeru-router-safety.yml` 工作流定义。
- 这不是 FatFish 整体合并，也不意味着所有工具调用入口都已完成相同的审计。

### 3. REA 依赖安全维护

- 主线 REA `package.json` 中将 Zod 固定到 `4.6.6`。
- 新增 `scripts/test_kdi_rea_dependency_security.py` 防回退检查。
- 该变更不等于完整依赖漏洞清零；`playwright-core` 及 MCP 工具行为注解仍在后续核查范围。

## 版本边界与注意事项

- 本次基于 **Kaeru/main**；FatFish/KDI-01 的隔离原型、Draft PR #6 中尚未合并的实现**不属于本次发行**。
- DSHA 开放协议标识仍为 `v1.2.0-std`，与发行版本 V1.1 相互独立。
- Gate、路径检查和宿主子进程不是操作系统级安全沙箱；工具能否运行取决于宿主依赖、配置和权限。
- V1.0 的已归档测试结果仅对应 V1.0 的旧提交，**不能自动视为 V1.1 测试通过**。
- 截至本说明编写时，未取得当前基准提交的可确认 CI 运行记录；新版本 Windows/Linux 安装、全量 REA 提供者、真实外部服务与完整 MCP `tools/list` 注解验收均应标为 **未验证/SKIP**，不得写作 PASS。
- V1.1 如需提供自定义 ZIP/TAR、SHA256SUMS 与 SOURCE_MANIFEST，应从**最终标签提交**重新构建、逐文件核对并记录哈希；不得复用 V1.0 资产。
